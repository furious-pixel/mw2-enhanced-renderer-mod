# MW2 ModernGL Renderer Notes

## Structure

- `render.py` is the game-facing entry point. It owns mod registration, hook callbacks, per-frame snapshots, runtime controls, loading/outro timing policy, and render-pass orchestration.
- `renderer/backend.py` owns `RendererResources`, the ModernGL resource construction/release container. Rendering behavior is not exposed as methods on this container.
- `renderer/scene_renderer.py`, `renderer/hud_renderer.py`, and `renderer/compositor.py` own ordinary rendering functions. Each function receives `RendererResources` explicitly; there is no composed renderer object, proxy, or delegation facade.
- `renderer/compositor.py` owns scene/overlay target recreation, complete-frame publication, loading-screen drawing, monitor-brightness updates, and final viewport composition.
- `renderer/diagnostics.py` owns renderer logging, timing reports, and diagnostic formatting as ordinary functions receiving `modstate` and the relevant snapshot or timing data.
- `renderer/resource_store.py` owns mission-generation CPU assets and render-node sidecars; no OpenGL object is stored in this layer.
- `renderer/object_lod.py` snapshots the native component-descriptor table and provides unambiguous installed-node/model-tree bindings. `renderer/entity_lod_assets.py` acquires each referenced POLY resource through the game's resource API during the loading safe point and retains its immutable WTBO bytes for the mission. `renderer/entity_components.py` owns the reusable live entity/component frame and renderer LOD policy; the frame references the current descriptor snapshot directly and stores only mutable entity bindings and node visibility alongside the compact live entity records. It selects from the resident assets without adopting the game's requested or installed detail.
- `renderer/terrain_gap_reduction.py` loads the mission-specific terrain placement corrections from `renderer/terrain_block_deltas.json`. The table identifies heap-allocated terrain blocks by stable geometry fields rather than session-dependent pointers.
- `renderer/mesh_plan.py` owns the stable typed face table shared by normal, enhanced-imaging, and satellite presentation adapters. Adapters are compiled lazily, and small per-block Numba dispatch is deliberately avoided in favor of future scene-batched numeric work.
- `renderer/numba_warmup.py` prepares every public production kernel before gameplay and reports disk-cache hits separately from actual compilation. Numba invalidates these entries from the source stamp of `geometry_numba.py`, not changes to unrelated Python modules; touching that kernel module can therefore rebuild all signatures it contains.
- `renderer/gl_resources.py` owns reusable OpenGL mesh/resource primitives. Main-scene ordinary geometry, main-view-only geometry, cockpit-only geometry, and target geometry each use an independent `DynamicGeometryResources` owner while sharing the context, shader programs, palette, and texture assets.
- `renderer/shaders.py` loads the external GLSL assets under `shaders/`; shader source is not embedded in the Python backend.
- `renderer/loading_screen.py` owns mission-local loading-shape decoding, sparse palette reconstruction, UI-ramp application, and native placement data.
- `renderer/resource_preload.py` owns mission-texture discovery, guest resource acquire/release calls, CPU texture assets, and the incremental and loading-barrier preload policies. OpenGL texture creation remains in `renderer/scene_renderer.py`.
- `renderer/hud_3d_views.py` owns target-display and right-MFD camera-state decoding, pane-relative projection setup, target model-root resolution, and rear/down/weapon view selection.
- `renderer/font_rendering.py` owns the replaceable FreeType boundary: font loading, native-size hinted grayscale glyph rasterization, shared glyph-atlas pages, text layout construction, direct layout-cache slots, and the font shader/draw resources.
- Files beginning with `_` remain disabled mod examples or alternates.

## Global Assumptions

- `mod_init.py` owns the complete configuration schema, including each key's
  section, safe missing/invalid fallback, scalar type, choices or bounds, and
  user-facing help. `load_mod_config()` normalizes this contract once into the
  complete flat `modstate.conf`; downstream renderer, HUD, and input code uses
  required values and does not repeat fallback policy. Renderer controls are
  derived only from `DEBUG`, `HUD`, and `renderer`, so `[input]` never enters
  renderer signatures or cache invalidation. `config_schema_records()` exposes
  detached metadata consumed directly by the standalone visual configurator.
  Shipped profile values may intentionally differ from safe fallbacks through
  explicit schema-owned overrides: `mod.conf` selects `ssaa_4x` over fallback
  `none`. The ignored private `joystick.conf` owns input bindings and policy;
  both its safe fallback and the shipped example disable joystick input.
  Schema inspection and normalization occur only at configuration load, never
  per frame.
- `tools/configure.py` owns the standalone pywebview configuration process and
  retains only visual grouping metadata beyond the mod-owned schema. It routes
  renderer, HUD, and debug edits to `mod.conf`, routes all input edits to the
  private `joystick.conf`, and restores schema-owned shipped defaults only
  after identifying both affected files in a confirmation dialog. Its PySDL2
  service opens and samples all physical axes only while the configurator is
  running; device names and physical axis ordering match the SDL contract used
  by DOSBox-X, and none of this discovery or polling enters the game runtime.
- Clean-room addresses are reloc addresses; `gamemem` handles runtime translation.
- Fixed clean-room addresses are read and written with explicit `gamemem.read_reloc_*` / `gamemem.write_reloc_*` helpers. The older unqualified `gamemem.read_*` / `gamemem.write_*` helpers remain compatibility aliases for reloc-address access, but renderer and new mod code should prefer the explicit names.
- Game pointer fields contain runtime linear addresses. The confusing `gamemem.read_reloced_ptr(...)` helper was removed; pointer fields should be read with a reloc or runtime scalar read appropriate to the field location, then treated as runtime addresses unless a specific structure proves otherwise.
- `gamemem.delta` exposes the active executable relocation delta. It is useful for diagnostics, but it must not be blindly subtracted from every pointer: live node-list pointers may point to heap/runtime memory below the executable base.
- `gamemem.read_runtime_*` methods read directly from runtime linear addresses without applying the executable delta. Geometry extraction uses these methods after reading the node-list head from the reloc-addressed list header.
- The renderer uses the mod viewport supplied by DOSBox-X. It should not assume that the mod viewport is the full backbuffer.
- DOSBox-X only invokes renderer callbacks after the Python helper module has a valid `modstate`; renderer code does not need to check for `modstate` itself.
- Core geometry preparation deliberately has no broad exception recovery around
  game-memory reads or extraction. Invalid executable layouts, stale contracts,
  and programming errors propagate to the hook boundary, where they are logged
  and re-raised instead of silently producing missing geometry.
- DOSBox-X gates renderer callbacks on the DOS process lifecycle for `MW2.EXE`: the landmark scan can complete while the executable is still loading, but render hooks and compositor/init callbacks are eligible only after the `LOADNGO` PSP is active and stop when that PSP terminates.
- Renderer resources live on `modstate`. DOSBox-X resets `modstate` when the active `MW2.EXE` PSP exits, and `RendererResources.__del__` releases GL objects as the old state drops.
- Active and model-tree membership is discovered authoritatively from game memory. The experimental native lifecycle-event projection and its renderer-side module were removed after measurements showed that validating the projection cost more than the discovery it replaced.
- `MW2_RENDERER_MUTATION_AUDIT=1` compares per-instance node fields, raw matrices, block/face headers, and validated index spans already read by extraction. It emits aggregated change and byte-offset distributions without extra game-memory reads, but its detailed Python byte comparisons are intentionally expensive and diagnostic-only.
- Renderer coordinates use game horizontal as `X`, height as `Y`, and depth as `Z`.
- Real-world geometry uses game horizontal as positive `X` and an unflipped projection matrix. Earlier notes expected an X flip in projection, but live mode-4 testing showed that mirrored world geometry; the game camera basis and extracted vertices already share the same handedness for this renderer path. Sky rendering also uses an unflipped X projection because it has no world handedness; flipping it makes camera roll appear reversed.
- Camera position is read as 16.16 fixed point; camera basis rows are read as 2^29-scaled unit vectors.
- Camera focal length is read from `camera_struct+0x18`, inferred as reloc `0xA7020` from the render struct base. This is after the game has selected cockpit/external zoom and clamped the 16.16 value, so the renderer uses it instead of the earlier zoom globals at `0xA6FA0`/`0xA6FA4`.
- At 1x zoom, focal length is 512 pixels. Higher zoom scales the projection matrix only; sky gradient geometry keeps its default-FOV angular size so zoom accurately magnifies the sky instead of preserving the game's screen-space gradient bug.
- The exported native near/far depths at relocs `0x15FFC8` and `0x15FF80` are retained in camera snapshots as fixed-depth metadata. Rendering keeps the enhanced far-plane policy instead of reproducing native far clipping. Only persistent cockpit camera mode 0 applies the native near rejection: the exported depth is converted from the game's `camera_forward_dot * 4` convention to renderer world scale and used as a shader clip plane for the ordinary world pass. The cockpit-owned subtree is redrawn with the same enhanced projection and the clip disabled, so its depth remains directly comparable with the world. External and transitional cameras do not enable this clip plane.
- Cockpit collision impacts and explosions are treated as complete instances before face emission rather than fragment-clipped at the cockpit boundary. The previous frame's smooth cockpit geometry supplies its farthest head-relative camera-forward depth and radial extent. Active collision-effect slots `0..255` with effect ids `0..22` are rejected by the radial extent before any effect model-tree walk; only nearby slots retain their render-node addresses and one spawn-latched head-centered transform. An intersecting instance is scaled radially from the smooth head, or translated forward when its anchor is not in front, until its anchor reaches the cockpit far depth plus a 10 percent margin. The same latched world-space transform is reused by other camera/eye views, while slot inactivity, identity change, departure from the cockpit vicinity, or mission reset releases all retained state. The tracker mirrors the fixed game pool and reuses its slot storage and node index; it does not retain a mission-wide history of distant explosion roots.

## Palette

- The game palette is dynamic and must be read every frame.
- The renderer stores the scaled 8-bit RGB palette in a 256x1 `RGB8` texture.
- Palette texture filtering is linear for all current palette users. This lets shaders interpolate palette-index coordinates smoothly before sampling the per-frame palette texture. A future path can switch specific resources to nearest if a render mode needs strict discrete palette entry lookup.
- CPU-side clear colors may still be derived from the same per-frame palette bytes for simple framebuffer clears.

## Render Targets

- The renderer does not draw scene content directly to DOSBox-X's default framebuffer. `RendererResources` owns double-buffered `RGBA8` scene color targets plus a shared staging depth renderbuffer. Their logical size is the mod viewport; their physical allocation size is selected once per OpenGL context by `[renderer] antialiasing`.
- The shipped `mod.conf` selects `antialiasing = ssaa_4x`, which allocates scene targets at twice the logical width and height and produces four physical samples per output pixel. The parser and resource-construction fallback remains `none`; that mode allocates scene targets at logical size and retains nearest sampling. Camera projection, culling, and screen-space geometry continue to use logical sizes, while scene viewports, billboard expansion, point size, and line width use the physical 2x scale. `[renderer] ssaa_line_width` additionally scales only scene-geometry GL lines while SSAA is effective; it is expressed in resolved output pixels at the 1024x768 reference, defaults to `1.0`, follows output-height scaling, and does not affect point size, HUD/radar strokes, or non-SSAA rendering.
- `RendererResources` also owns double-buffered native-resolution `RGBA8` HUD overlay targets with no depth or stencil attachment. Their size always follows the mod viewport, so HUD geometry, text, sprites, borders, and antialiasing remain independent of scene supersampling. Side-by-side mode still uses one half-window width and the full window height for each logical viewport.
- Scene and overlay rendering always target the staging pair. After the late overlay pass at `0x0002CEC1`, `compositor.publish_frame(resources, frame)` atomically swaps both color-target pairs and records the published game-frame id. The presentation compositor samples only the published scene and overlay, so a DOSBox-X presentation that occurs between MW2 render hooks shows the previous complete mod frame rather than mixed or partially cleared targets. Depth is not published because the compositor never samples it.
- Renderer-owned frame pacing is explicitly opt-in and applies only to mod-only presentation after the first gameplay frame has been published. `modgl.notify_frame_ready()` reports that a new complete scene/overlay pair has been submitted; it does not wait for GPU completion. DOSBox-X then invokes the compositor and posts the buffer swap from its outer loop while timer, interrupt, audio, and event servicing remain active. Loading, game-only, side-by-side, and target-FPS-zero operation retain VGA-driven presentation. Switching to side-by-side therefore releases the game-frame gate even when the session has a configured target FPS.
- `[render] mod renderer host vsync` independently requests OpenGL swap interval 1 after the SDL2 context is current and verifies the active interval. It does not select DOSBox-X's `[vsync] vsyncmode=host`, so host presentation synchronization cannot change emulated VGA timing. The fullscreen 60 and 72 FPS launchers enable this setting while retaining `vsyncmode=off`; uniform fixed-refresh presentation requires a host refresh that is an integer multiple of the selected target, such as 120 Hz for 60 FPS or 144 Hz for 72 FPS. The cooperative game-frame wait remains before rendering, while the final swap may block for the remaining presentation interval. No additional scene work, upload, or synchronization primitive is introduced.
- New-scene readiness and time-varying composition are separate contracts. A compositor-only effect calls `modgl.set_continuous_presentation(True)` to request repeated composition of the last published textures at the configured target cadence, then releases that request with `False`. Continuous presentation does not repeat geometry extraction or synchronize the CPU and GPU. It exists for effects whose output changes with wall time despite no newly published game frame; DOSBox-X does not know which effect requested it.
- The scene framebuffer's logical size follows the mod viewport passed by DOSBox-X. In the current side-by-side development layout this is the configured single-side resolution, typically 1024x768, not the doubled window/backbuffer width. Under 4x SSAA only its physical color/depth allocation becomes 2048x1536.
- Target-display and right-MFD 3D views each own a separate color/depth framebuffer whose logical size is the exact camera pane. They follow the active scene sample scale, so 4x SSAA allocates each at twice its logical width and height and linearly downsamples it into the native HUD pane before the corrected one-pixel border is drawn. Satellite-damage rendering uses the same allocation contract but enlarges its reduced-resolution scratch image into the main scene target. Under SSAA that existing stretch pass samples the exact center of each source 2x2 group and writes the resolved color into a constant 2x2 block in the main scene target; the final compositor therefore averages identical values instead of filtering the damaged image twice. Native rendering retains nearest sampling. Auxiliary views do not repeat the live node-list walk: ordinary geometry reuses the primary extraction, while renderer-owned entities select and transform resident mesh plans for that view's projected resolution. MFD and target drawing share one camera-target renderer, and no additional scene walk, geometry extraction, framebuffer, or draw pass is introduced.
- Supersampled main-target creation is attempted before auxiliary camera targets are allocated. If any supersampled scene or camera target later fails to allocate, the renderer releases the supersampled targets, permanently selects `none` for that OpenGL context, recreates native targets, and retries the failed allocation once. Requested and effective modes remain available on `RendererResources`; subsequent viewport changes in that context do not retry SSAA.
- Sky, gradient, and world geometry are rendered into the scene framebuffer from the render-aware CPU hook at the game's HUD-entry callsite (`0x0002CEB7`), followed by the HUD overlay draw into its own framebuffer. The mod hook engine observes callsite addresses, so the `hud_entry` function address `0x0003BB70` cannot itself be registered as a `"call"` hook; `0x0002CEB7` is the callsite that invokes it.
- Depth testing is disabled for sky and gradient rendering. Mode-4 world geometry renders with `DEPTH_TEST` enabled against the scene framebuffer depth attachment.
- FreeType glyph coverage is emitted as premultiplied RGB plus coverage alpha. Text and antialiased HUD primitives drawn onto otherwise transparent overlay pixels use separate RGB/alpha blend factors: RGB uses premultiplied-over while alpha is replaced by source coverage, so the final compositor does not fade already-premultiplied RGB a second time. Text drawn over opaque UI backdrops such as the Escape menu and short-message bars uses normal premultiplied blending. Hard-edged overlay writes such as sprites, fills, borders, slider pieces, message bars, and other non-antialiased primitives render with blending disabled.
- HUD glyphs are rasterized with normal hinting at their final native sizes: 16 px for source uppercase and 13 px for the 80% small-cap form. Glyph bitmaps share lazily allocated 1024x1024 single-channel `R8` atlas pages with one transparent texel of padding. Atlas sampling is nearest, UVs cover the complete bitmap bounds, and text origins are snapped to pixel boundaries; FreeType's grayscale coverage supplies antialiasing without a second GL downsampling pass. Each visible glyph contributes a two-triangle quad, and all glyphs for a text run that occupy the same atlas page are uploaded and drawn as one batch instead of one texture bind, buffer write, and draw per character.
- UI text uses synthetic small caps inside `font_rendering.py`: source uppercase characters retain the requested size, source lowercase characters select their uppercase glyph at 80% size, and measurement/drawing share mixed-size advances, kerning, and a common full-size baseline. Prepared vertex batches are cached in caller-owned `TextLayoutSlot` objects rather than a dictionary inside the font renderer. A slot retains one `(text, spacing, size)` layout and replaces it when that rendering site changes, so rapidly changing counters cannot grow or churn a global text cache.
- `RendererResources` owns the persistent layout slots because HUD snapshots are rebuilt every frame. Cockpit panel text uses a fixed 101-slot table: direct native-panel sites, four MFD HTAL labels, both twelve-label compass cycles, and 47 altimeter labels each retain a dedicated slot. Fixed compass and altimeter layouts are prewarmed once for each resolved font size. Mission objectives use fixed title/footer slots and 128 indexed row groups. Menus perform one integer dictionary lookup by the native page address, then use direct title, marker, item-label, and item-value slot arrays for that page. Future fixed HUD panels should follow the direct-table model; data-driven page families may use one outer lookup followed by indexed slots.
- The final composite pass binds `ctx.screen`, sets the compositor viewport, disables depth/blend/cull state with `enable_only(moderngl.NOTHING)`, and combines the published scene and premultiplied overlay textures in one fullscreen-quad shader. Native scene targets retain nearest filtering to avoid driver-dependent pixel bleed. A 4x SSAA scene uses linear filtering during this existing sample; at the exact 2:1 axis ratio, each output pixel averages the corresponding 2x2 source neighborhood without an additional resolve texture or draw. After composition, the shader applies the live monitor-brightness step from reloc `0x000A582C` through the selected 64-byte DAC response row at reloc `0x000B4F90`. It linearly interpolates the row's normalized samples independently per RGB channel, retaining the native nonlinear response in which shadows fall faster than highlights without reproducing the original 6-bit palette quantization and posterization.
- A mission outro hook at callsite `0x0003FC2E` records the native blocking palette fade start time in shared `modstate` and requests continuous presentation when renderer-owned pacing is active. The compositor multiplies the complete scene-plus-overlay result toward black over 1.284 seconds, calibrated from a measured native interval of 1.2841929 seconds, then presents the fully black endpoint and releases continuous presentation. The compositor still performs no game-memory reads. A game-specific per-fade-step presentation hook is intentionally not used: it would follow the native palette-step rate instead of the configured renderer cadence and would couple the generic presentation scheduler to MW2's blocking fade implementation.
- Four call-only mission-loading hooks own the loading presentation lifecycle: `0x0002CD11` begins with black, `0x0002C4E2` snapshots the background and embedded palette, `0x0002C5B9` snapshots all strip frames plus the UI ramp, and `0x0002CE42` starts the mission preload barrier. At the final hook, initialized texture tables are converted into the existing preload request set and DOSBox-X ends the current decoder slice. The host keeps guest progression paused while the safe callback processes bounded 16-resource CPU batches; a requested next safe point chains the following batch, while wall-clock presentation deadlines allow complete loading-screen composition and swaps between batches. Once CPU acquisition is complete, `scene_renderer.py` creates the complete indexed-texture cache in one final GPU phase. No `glFinish` is required: with no next safe point pending, the outer loop performs one final complete loading presentation and then releases the guest.
- Guest resource acquire/release calls recursively enter the DOSBox machine loop. While that nested execution marks `guest_call_active`, safe-point barrier presentation and lifecycle changes are forbidden, and every OpenGL presentation entry point retains the current front buffer instead of clearing or swapping without Python composition. Only the outer machine loop may present or release the barrier. This re-entrancy rule is required to prevent a transient full-black loading frame and to keep the barrier alive across all resource calls.
- Loading handoff remains closed after preload completion until the first complete enhanced scene/overlay pair is atomically published. This hides first-frame geometry extraction, HUD preparation, and initial GPU scene uploads behind the loading artwork; a two-second timeout and unavailable-capability paths fail open so loading cannot become stuck. Once that complete pair exists, side-by-side modes end the loading override immediately so the live native and enhanced views become visible together. Mod-only presentation immediately begins a 0.25-second fade-out; there is no additional fully lit post-handoff hold because preloading already provides the readiness barrier. `disable_mission_texture_preload` remains a diagnostic fallback, and requests made outside the loading barrier retain the bounded incremental policy. CPU snapshots live only on the mission's fresh `modstate`; loading decode bypasses the process-global HUD sprite cache because Python modules survive executable restarts. The compositor reads no game memory and creates no loading FBO: it clears only the supplied `ctx.screen` viewport and draws mission-local indexed background/strip textures through a dedicated nearest-filtered palette texture. The initial fade-in lasts 0.5 seconds, and the five strip frames continue cycling at the native 330 ms cadence while loading remains visible. Strip timing advances at most one layer per compositor call and discards missed ticks.
- `hud_cockpit.py` currently owns the shared cockpit snapshot for the weapon list, power meters, right MFD, compass, and altimeter, retains fixed rendering-site indices for text, and emits generic text, outline, filled-rectangle, and indexed-sprite commands consumed by `renderer/hud_renderer.py`. Player, mech, body, panel, pane, text-position, weapon, control, meter, and MFD fields are read as contiguous structure spans where practical rather than one game-memory call per scalar field. `mech+0xA0` remains authoritative: mode 1 selects startup weapons from `panel+0x78`; mode 2 selects steady weapons, power meters, MFD, compass, and altimeter; other modes emit no current cockpit elements. Startup and steady weapon labels both use the configured `panel+0x34` pane-local text position so the callback handoff does not shift the readout. The shared native player, mech-owner, and master-HUD gates are evaluated before reading panels.
- The steady power-meter replacement includes signed KPH text, the MASC presence label, throttle/heat/heat-rate/jump-jet bars, and the `ΔH/Δt` heat-rate label. The `[HUD] power_meters` setting selects `native` four-band shading or `enhanced` smooth native-style shading. Enhanced segments retain the native fill geometry and base palette family, then use live palette colors at configurable dark, lit-edge, and peak offsets; two vertex-colored spans interpolate from the lit edge to an off-center peak and from that peak to the dark edge in the existing single batched HUD rectangle draw. Fixed meter state is read through reloc base `0x0A6900`; clean-room runtime addresses around `0x266900` were captured with delta `0x1C0000` and must not be used as process-stable addresses. Heat width is the interpolated 16.16 value shifted by 16, jump-jet geometry is suppressed when raw charge at `mech+0xC0` is negative, and near-full interpolation residue is rounded so a charged bar has no one-pixel remainder. The throttle derives a 15-pixel interior from its 17-pixel-wide inclusive outer rectangle and one-pixel border. Its zero state is one complete interior row, while scaled nonzero extents retain inclusive endpoints so full forward and reverse fills reach the inside border. The enabled-by-default `[HUD] alt_throttle_indicator_position` groups the bar, signed speed text, and active MASC text in a right-center panel whose top and bottom mirror the enhanced altimeter strip. It preserves the native two-to-one forward/reverse split rather than aligning neutral to an altimeter marker; disabling it restores the original panel locations. The alternate labels use the existing persistent text slots and deliberately bypass native-pane clipping, and all bar segments remain in the existing batched HUD rectangle draw without new per-frame GL objects.
- Native meter shading expands each logical color segment into edge/main/edge/dark bands across its thickness. Enhanced meter values retain fractional fixed-point extents through panel/output scaling and snap only their completed physical-pixel edges, clips, and gradient peak; native mode retains its source-grid quantization. `RendererResources` owns one grow-on-demand HUD rectangle byte buffer whose write cursor resets for each batch. Rectangle, border, and gradient vertices are packed directly into that retained storage and uploaded through a bounded memory view, replacing per-batch Python arrays and serialized byte copies. All filled bands for a batch are submitted in one `GL_TRIANGLES` draw; outlines and text remain separate.
- The right MFD reproduces native mode dispatch: mode 0 emits nothing; mode 1 draws the damage wireframe plus clipped palette-recolored region copies; mode 2 draws data-driven H/T/A/L labels and current/remaining armor bars; modes 3-5 render rear, down, and weapon views into the dedicated MFD target, then draw the palette-6 frame. Their native bitmap labels are neither read nor preloaded. Fully started camera modes instead draw the runtime-font texts `rear`, `down`, and `wpn` centered nine reference pixels below the frame's exclusive bottom edge. Lowercase selects the smaller uppercase glyph form, the text uses the frame border's live palette index `0x06`, and three distinct layout slots prevent camera-mode switches from replacing cached text. The target-name row uses the same nine-pixel frame-relative offset and its range row remains 16 reference pixels lower. `[HUD] htal_meters` independently selects native four-band armor-bar shading or the same enhanced live-palette two-span gradient used by power meters; armor values, split sections, damage thresholds, dimensions, and color-family selection remain unchanged, and all segments stay in the shared batched HUD rectangle draw. Rear/down walk the complete local-player model subtree and identify exactly its attached render-node addresses. The main extraction partitions those nodes into a main-view-only dynamic draw set while placing every other dynamic node in the ordinary draw set. The main view draws both sets; rear/down reuse the same extracted geometry and draw only the ordinary set. Independent nearby effects, projectiles, smoke, terrain, and other units therefore remain eligible without a second scene walk. Weapon view consumes the game-maintained ordnance pose without player-subtree exclusion and reuses the complete ordinary scene resources. The `[HUD] rear_camera_mirror` setting horizontally reverses only the completed rear-view texture during pane composition, producing vehicle-mirror behavior without changing camera geometry, culling, the pane frame, or the camera label; it is enabled by default. The damage base uses the common source origin implied by the part clip-window offsets.
- The steady post-panel pass draws the compass and altimeter only through their individual enable flags. The `[HUD] compass_altimeter` setting in `mod.conf` selects one exclusive path: `native` retains the original compass and altimeter RLE strips plus the game's original compass direction, while `enhanced` does not read the strip/indicator RLEs or HUD style offset. Enhanced ticks and the six solid rectangular indicators share one immutable position/palette-index vertex buffer uploaded when `RendererResources` is created. Their four diagonal carets use the analytic indexed-alpha atlas generated by `renderer/hud_atlas.py`; the same atlas owns generated target carets, target brackets, and the selected-NAV circle. Python atlas bytes and fixed UV quads are cached by their ceiled physical size, then one atlas texture and one static VBO are uploaded per GL context or physical-size transition. The sprite shader samples the live palette, and integer-sized nearest-filtered atlas quads are placed only on integer output coordinates. Each frame therefore selects static ranges or visible atlas entries and supplies transforms without generating atlas data, creating GL objects, or uploading vertex buffers. Enhanced heading and altitude inputs retain their fractional fixed-point values through output scaling, then the complete generated scale origin is snapped once to the nearest physical pixel; ticks, labels, and attached indicators share that snapped translation so the internally rigid geometry cannot stretch or wobble. Enhanced tick geometry follows panel scaling, while immutable fixed-label objects use dedicated prewarmed text slots and follow font scaling; the repeated compass data includes both `00` instances required at the wrap. Both runtime modes derive absolute heading from body yaw at `body+0x60`; torso yaw at `body+0x6C` retains the native shaded bar, scaled moving dot, and paired center sprites. The altimeter retains the documented bias, signed division, 16.16 shift, below-reference clamp, fixed reference marker, moving altitude marker, and target-elevation carets; target altitude resolution still covers direct, primary-entity, and secondary sources. Pixel placement and spacing are specified in `docs/HUD_LAYOUT.md`.
- Targeting and radar HUD replacement are part of the same cockpit snapshot rather than separate hooks. Target-display startup/shutdown panes are latched through the native panel transition controller, target text uses the slot-14 steady callback data, and center/offscreen target markers use the shared reticle projection globals. The center weapon reticle remains a native RLE; four-corner brackets, four complete offscreen directional carets, and the selected direct/NAV circle are static entries in the generated HUD atlas. The 768p bracket uses 9x9 corners whose curved outer tips fade across their final pixel. Effective scene projection retains one fractional center and one nonnegative fractional radius through output scaling; the renderer then rounds the completed physical-pixel center and truncates one shared physical-pixel radius for all four corners. Horizontal and vertical expansion therefore remain synchronized without a minimum enclosure or premature 768p quantization. One immutable bracket command replaces four per-frame corner records. The selected NAV label is runtime font text. These generated target markers do not read target-marker RLE resources or HUD style offset, and their visible pixels are recolored per draw through the live game palette. Selected direct/NAV targets remain eligible in full-screen weapon view because the camera gate suppresses only the center reticle; satellite mode suppresses the ordinary center reticle and uses its own radar-space selected-target indicator. Steady panel slot 17 independently displays the data-driven `AUTOPILOT` label when `mech+0xBC` is state 1 or 2. Radar owns `hud_radar.py`: mode 1 alone follows the configurable widescreen panel anchor; mode 2 uses the same animation extent but remains centered in the output viewport; and mode 4 retains its separate full-viewport satellite transform. Radar projection retains fractional blip and sprite coordinates until final output-pixel placement. Mode 4 draws an onscreen selected target as one symmetric resolution-aware cross and an offscreen target as the shared full-size generated caret. Decoded radar VFX sprites are cached by resource index after the first lookup. The `[HUD] radar_stroke_width` setting controls radar-circle and FOV-line thickness in output pixels, defaults to `1.5`, and is clamped to `0.5..8.0`; both signed-distance shaders use linear one-output-pixel coverage at the stroke edge so their antialiasing and apparent weight remain consistent.
- `hud_menus.py` decodes handler-tagged page stacks, numbered/action/status rows, callback-driven value strings, F12 mission objectives, and slider values while retaining the native menu state machine for input, navigation, callbacks, sounds, and setting mutations. Handler records, handler data, panes, page headers/item arrays, callback parameters, slider styles, objective records, and entity/panel tables use contiguous reads where their structure bounds are known. Active pages, pending pages, and active-handler ids are collected in one linked-list traversal per hook instead of separate walks.
- The HUD-entry hook at `0x0002CEB7` draws F12 objectives plus handler `5` user-systems and handler `6` command-computer pages after the weapon/rest-of-HUD pass. The late hook at `0x0002CEC1`, after native `menu_handler_update`, draws handler `4` Escape pages and the two fixed top/bottom short-message records before publishing the frame. This preserves native layering: regular HUD/F12/U/B first, Escape/status messages last.
- `hud_messages.py` snapshots the two native short-message records at relocs `0x0A5600` and `0x0A5624`, follows their runtime text pointers, respects active/expiry state, and derives screen text origin from the native pane/window plus pane-local record coordinates. `renderer/hud_renderer.py` draws all active 1024x48 beveled message bars first with blending disabled using the 48x48 `textures/msg_bar_tex_dark.png` caps-and-stretched-center texture, then draws all active message text in one premultiplied text pass over the opaque bars.
- `hud_sprites.py` owns the shared indexed VFX RLE decoder and keyed game-resource-cache lookup used by menus and MFD sprites. A payload is decoded once in Python and uploaded once per GL context; the sprite shader can either preserve its native palette indices or override visible pixels with one damage-state palette index while retaining RLE transparency and per-draw clipping. Menu backgrounds, selection markers, and sliders use the same path. The generic last-back-row rule uses the handler's visual-slot count so the `0` escape/back row is anchored at the panel bottom. The Escape brightness slider reads the live applied shadow value immediately, and the late menu hook refreshes the compositor's brightness snapshot after native slider updates so adjustment is visible without waiting for the next scene frame.
- The renderer intentionally avoids GPU readback/synchronization calls such as framebuffer reads, `glFinish`, or `glFenceSync`. Performance-sensitive uploads should use streaming patterns rather than forcing CPU/GPU synchronization.

## World Geometry

- `renderer/geometry.py` owns clean-room node-list extraction and mode-4 lighting. `render.py` snapshots its output once per HUD entry latch (`0x0002CEB7`), `renderer/backend.py` owns the GL programs and buffers, and `renderer/scene_renderer.py` owns their upload and drawing behavior.
- Scene snapshots retain the extractor's single geometry result object instead of flattening every buffer into parallel snapshot fields. Main-scene and target-display uploads share the same dynamic-buffer synchronization path, while static scene buffers retain their signature-based reuse. Static/dynamic uploaded-content flags are refreshed at upload time so main, MFD, and target draws do not rescan every mesh dictionary merely to detect empty geometry.
- Target-display geometry is extracted separately from the object-owned model-tree root prepared at callsite `0x00047887`, rather than reusing the camera-dependent main scene list. This preserves complete high-LOD target geometry even when the object is outside the main camera or satellite mode selected a lower scene LOD. Target vertex decode and matrix transformation run as contiguous Numba batches, using the matrix already present in each live tree record. Mode 1 uses a wireframe-only extraction path that skips solid/textured emission and texture work. Mode 2 converts textured face materials to their fallback palette family during face classification, before unused textured vertices can be decoded, and defaults to native-like untextured flat-lit rendering; the textured three-point-light experiment remains available behind `TARGET_DISPLAY_ENHANCED_RENDERING` but is disabled.
- Geometry walks the renderable node list at `0x104580+0x08` by reading the head pointer from the reloc-addressed list header, then staying in runtime-address space for list links, `entity_ref`, and `block_data`. It caps traversal at 1000 nodes.
- Node headers, polygon block headers, vertex arrays, face headers, entity matrices, and face-index spans are read with bulk runtime byte reads and parsed in Python. This avoids the earlier per-scalar Python/C memory-call cost that severely limited frame rate.
- Face-header parsing also records the vertex payload families required by each block (legacy positions, illuminate colors, billboard control UVs, and mode-5/6/7 data). Vertex decode consumes those recorded requirements directly instead of rescanning the composed Python face tuples after topology processing.
- The polygon-block face offset check is deliberately relaxed for live node-list entries: `face_data_offset` must be at or after `0x18 + nvert * 0x2C` and below the sanity ceiling, but exact equality is not required. The exact equality signature is only appropriate for brute-force memory scans and can incorrectly reject trusted blocks that carry padding or extra data.
- Terrain-versus-entity coordinate sourcing follows the node `flags` high byte, matching the clean-room geometry specification: `0x08` is treated as terrain-like for coordinate sourcing and uses cached world-coordinate vertex fields at `+0x0C/+0x10/+0x14`; every other high-byte value is treated as entity/object geometry and defaults to transforming local coordinates at `+0x00/+0x04/+0x08` through the row-major matrix at `entity_ref+0x3C`. The precise game meaning of `flags>>24 == 0x08` still needs reverse engineering.
- The enabled-by-default `[renderer] reduce_terrain_gaps` path applies mission-specific whole-block X/Z translations before terrain face emission. Each block is matched before modification by `(nvert, nfaces, sum_x, sum_z)`, where the sums use the untouched signed 16.16 cached-world X/Z vertex fields. Runtime, heap, and runtime-minus-delta block pointers are intentionally not identities because terrain allocation changes between mission loads. A match converts the block vertices to floating-point fixed space, preserves Y, and adds the table's fractional world-space `(dx, dz)` correction; static geometry caching then retains the corrected result. Disabling the option bypasses the lookup. Only `terrain_block_deltas.json` is consumed; residual seam-pair welding/skirting is intentionally deferred.
- The polygon block `state_flag` at `block_data+0x00` is still tracked before any face-mode filtering. Static-buffer caching is only applied when a node is both terrain-like by `flags>>24 == 0x08` and has `state_flag != 0`; non-`0x08` nodes with nonzero `state_flag` still go through the dynamic/entity path so stale cached world fields cannot place culled objects at the origin. Live testing confirmed this fixed the origin pile-up.
- `MW2_RENDERER_ENTITY_VERTEX_MODE=cached` remains only as a diagnostic fallback because cached entity world fields can be stale for nodes the original renderer culled.
- Cockpit geometry uses a structurally selected smooth transform path in camera mode 0. The renderer starts at the live player cockpit subtree, snapshots model-tree local FP29 rotations, 16.16 translations, and attached render-node addresses after the native update, composes the hierarchy in `float64` without native per-parent rounding, and transforms the rendered cockpit mesh blocks directly from immutable model-space vertices. The cockpit camera is corrected from the same smooth camera-attachment solution, preserving native gait, slope response, articulation, eye pan, and eye tilt without temporal filtering or frame history. Smooth positions remain `float64` through CPU batching and are converted to the renderer's ordinary `float32` GPU vertex layouts only at final emission; all non-cockpit entities retain the established integer transform path. The hierarchy resolver is a module-level recursive helper rather than a per-frame self-recursive closure, allowing each temporary node snapshot to be released immediately by reference counting instead of accumulating until cyclic garbage collection. The attached-node set also selects the cockpit-only geometry partition used to redraw the cockpit without the mode-0 world near clip.
- The initial world pass emits palette-index triangle faces for modes 0, 1, and 4, palette-index closed polyline segments for mode 2, textured billboard/sprite quads for mode 3, and textured surface triangles for modes 5, 6, and 7. Any other modes are still skipped for now.
- Mode 0/1 triangle and mode 2 line buffers upload `x, y, z, palette_index`, with coordinates converted from 16.16 fixed point to float and with no CPU-side X negation. Mode 4 uploads `x, y, z, c_in, face_light_contribution`, and modes 5/6/7 upload `x, y, z, u, v, face_light_contribution`. The geometry projection is unflipped so output is not mirrored.
- Lighting is computed on the CPU per face from the game light/fog globals and face normal. Mode 1 still uses the game-like integer lighting-plus-view-fog offset on the CPU. Modes 4/5/6/7 instead upload only the continuous per-face light contribution from the traced normal/light calculation and leave the enhanced per-vertex fog step to the shader. Mode 0 bypasses lighting/fog and uses `(face_flags >> 4) & 0xFF` as a direct palette index.
- Mode 1 ignores vertex `c_in`; it emits a flat palette index of `(s_field << 4) | offset` for every vertex in the face, where `offset` is the computed lighting/fog value.
- Mode 2 ignores lighting/fog and emits closed line segments between consecutive face vertices plus the final-to-first closing segment. Its palette index is `(face_flags & 0xFF0) >> 4`.
- Mode 3 canonicalizes a logical billboard from adjacent reversed-winding source faces that share the same descriptor and control-role vertices. The authoritative spine is `A=(u=0,v=0)` to `B=(u=0,v=max_v)`; triangle index order is ignored except as a fallback when those roles are missing. The billboard descriptor index is `(face_flags & 0xFF0) >> 4`, with no `+0x100` offset.
- Mode-3 geometry buffers no longer hold world-space expanded quads. They store the world-space `A/B` spine endpoints plus per-corner edge/side flags, and the textured shader expands the final quad after projection in screen space.
- Mode 5 uses descriptor index `(face_flags & 0xFF) + 0x100`, keeps the base/unremapped CEL texture, and classifies each CEL's 16 remap tables once at texture resolution into `identity`, `darkening`, `darkening_2color`, `fog`, or `split_fog`. The shader samples the indexed texel, looks up base RGB through the per-frame palette texture, then applies the classified continuous blend: per-channel dark-ratio scaling for darkening textures, linear fog-color mixing for fog textures, and a two-ramp S=8 midpoint for split fog.
- Resolved indexed-texture CPU assets and uploaded texture entries retain both the numeric resource id and the corresponding CEL name. `renderer/texture_catalog.py` owns the stock resource-id/name catalog and name-family predicates, so future material-specific rendering can classify a resolved texture by stable human-readable identity without consulting or rereading game files.
- The enabled-by-default `[renderer] enhanced_heli_rotors` path recognizes the stock two-sided helicopter main-rotor disc topology, replaces each authored seven-vertex side with a 64-segment triangle fan, and remaps it across the complete rotor texture. Its fragment path reconstructs keyed RGBA samples, applies an angular radial blur and soft circular coverage, and renders the resulting translucent disc with depth testing enabled, depth writes disabled, conventional source-alpha blending, and independent rotor batches sorted back to front. Disabling the option restores the authored geometry and blocky animated texture used as a stand-in for motion-blurred rotor blades.
- In enhanced-imaging and satellite views, enhanced helicopter rotors omit both the textured fill and black depth occluder and emit one 64-segment circular wireframe rim for the coincident two-sided disc. The rim uses the applicable view/owner color. This rotor exception does not alter the ordinary enhanced-imaging or satellite wireframe layouts for other faces.
- The independent enabled-by-default `[renderer] enhanced_aero_lift_fans` path applies the same radial-blur, alpha-blended, back-to-front transparent material to stock aeroplane enclosed lift-fan CELs. It preserves the authored fan geometry and UVs and adds no special wireframe rim; satellite and enhanced-imaging presentation therefore continue through their ordinary face policies. Disabling the option restores the original blocky animated lift-fan texture path.
- Modes 4/5/6/7 now share a continuous version of the game's view-depth fog shape from the clean-room shading specification: `max(0, dot(world_pos - camera_pos, camera_forward)) * 4 / fog_distance`. This fog is applied in the shader per vertex so interpolation stays smooth and the static-geometry cache does not freeze terrain fog as the camera moves, while avoiding the earlier enhanced-only global fog reduction.
- Mode 6 currently shares the same enhanced textured-surface path as mode 5: same `tex_idx + 0x100` descriptor lookup, same base-texture palette sampling, same continuous per-face darkening, and the same repeat-wrapped UV handling. The clean-room distinction is only the original software renderer's UV pre-scale behavior; because this renderer extracts node-list geometry directly instead of replaying that rasterizer setup, mode 6 is intentionally handled the same way as mode 5.
- Mode 7 currently shares the same enhanced textured-surface path as mode 5: same descriptor lookup, same base-texture palette sampling, same continuous per-face darkening, and the same repeat-wrapped UV handling. This is an intentional enhanced-renderer deviation from the original affine mode-7 rasterizer; we do not emulate the software renderer's affine texture distortion.
- Per-vertex color uses the low byte of vertex `+0x18` as `c_in`. Mode-4 vertices with `c_in < 0x30` are emissive and pass through directly to the palette index, bypassing both lighting and enhanced fog. Vertices with `c_in >= 0x30` keep the documented `VFX_illuminate_polygon` ramp selection from `c_in`, but the renderer now applies the per-face light contribution plus enhanced per-vertex fog in the shader and samples the dynamic palette texture from the resulting continuous palette index.
- Laser/projectile colors are fixed by the same general mode-4 `c_in` rule rather than by object-specific detection: known laser values (`0x0D/0x0F`, `0x21/0x25`, `0x2D/0x2F`) are below the `0x30` emissive threshold and therefore render full-bright regardless of scene lighting/fog. The earlier signature-based `cc_lo=15` diagnostic was intentionally removed because it was not the real game rule.
- The mode-4 shader uses normal GPU perspective interpolation for palette indices. This is an intentional enhanced-renderer deviation from the old software renderer rather than preserving its screen-space interpolation artifacts.
- Mode 3 reads billboard texture descriptors from reloc `0x13DFE0`, resolves pages through the cell table at reloc `0x13FBE0`, and reads live cached `CEL\0` data. The cell-table pointer form for billboards is `CEL_header + 0x10`, matching the width/height fields recorded by the dump tooling; the resolver subtracts `0x10` and reads the CEL header at that runtime address. The first descriptor `i16` at `+0x00` selects the page, and the descriptor `u16` at `+0x02` selects the page sub-entry / animation frame; the renderer no longer collapses a page to its first valid CEL, because that froze explosion billboards on frame 0. Descriptor reads suppress draw when `u16 +0x06 == 0` (completed/stopped) or `i16 +0x08 < 0` (disabled), matching the game's `texture_descriptor_lookup` gating. CEL pixels stay as 8-bit palette indices in an `R8` GL texture with nearest filtering; the shader discards palette index `0xFF` and then samples the per-frame palette texture for RGB.
- Uploaded indexed textures remain shared, persistent GPU cache entries, but cache residency does not authorize a draw. Each main-scene, cockpit, target, and MFD geometry owner records the descriptor indices resolved for its current CPU snapshot; every billboard, mode-5/6/7 surface, and enhanced-rotor draw must also find its descriptor in that owner-local active set. Completed or disabled animations therefore stop drawing immediately even though their last uploaded texture and geometry remain cached.
- Mode 5 uses the same descriptor and page tables, but selects `desc_idx >= 0x100` and resolves the page sub-entry using the descriptor selector at `u16 +0x02` (exact match or clamp-down to the nearest lower valid sub-entry). Mode-5 textures keep nearest sampling, enable repeat wrapping, do not discard palette index `0xFF`, read all 16 texture remap tables from reloc pointer `0x0A6DCC`, and classify opaque texels by weighted remap behavior according to the clean-room remap specification. The classifier preserves `darkening_2color` separately from `darkening`, derives `fog_color`, `dark_ratio`, and `s8_ratio` from the brightest opaque texel, and discards near-white palette results in the fragment shader (`rgb > 0.94` on all channels) to match the existing enhanced textured-path transparency convention. The texmap vertex shader applies enhanced per-vertex fog before converting the per-face light contribution into the `0..1` intensity used by the fragment shader.
- Geometry is drawn after sky and gradient into the offscreen scene framebuffer with depth testing enabled. This intentionally departs from the original painter-order renderer to avoid preserving old software overdraw artifacts.
- Geometry extraction writes periodic diagnostics to `mw2mods/renderer_debug.log`, including runtime delta, runtime and optional reloc-equivalent node/block addresses, terrain/entity counts from node flags, state-flag counts, entity/state mismatches, static/dynamic buffer counts, entity matrix usage and bounds, static cache hits/misses, relaxed-offset counts, runtime byte-read counts, extraction time, face-mode counts, emitted triangle/line/textured counts, texture lookup/read counts, and position/palette/UV bounds.
- Geometry output is partitioned into static and dynamic families. Ordinary unindexed flat triangles and mode-4 illuminate triangles remain expanded vertex streams. Indexed flat geometry uses a position VBO, a `uint16` triangle EBO, and a palette value per triangle in primitive order. Modes 5/6/7 use descriptor-grouped position/UV VBOs, `uint16` EBOs, and per-triangle contribution textures in the same primitive order. Mode-3 billboards and explicit point/line streams retain their specialized expanded layouts. Face-dependent lighting and contribution data must remain aligned with EBO primitive order; vertices shared by faces with different lighting are not used to collapse the ordinary expanded mode-4 path.
- Enhanced-imaging main-scene geometry has a separate indexed wireframe layout for each static/dynamic partition. One tightly packed `float32 xyz` VBO is shared by a `uint32` triangle EBO for black depth occluders and a `uint32` line EBO for closed colored edges. The occluder program always samples palette index 0. The line program reads one `float32` palette index per `GL_LINES` primitive from a nearest-filtered primitive texture through `gl_PrimitiveID`. This layout does not replace or alter the ordinary flat/illuminate/textured EBO families, so their face-lighting alignment remains independent.
- Enhanced-imaging extraction caches typed face counts, `uint16` local indices, owner slots, occluder gates, and explicit line/polyline records. Static terrain positions/topology and completed indexed wireframe buffers are built once and reused. Dynamic vertex bytes are reread and transformed each frame; each unique live owner palette is refreshed once per extraction before a count-first/fill-second Numba pass creates the dynamic VBO/EBO arrays. Enhanced imaging skips ordinary solid/textured emission that its pass will not draw while preserving explicit point, line, and polyline semantics.
- With `[renderer] enhanced_enhanced_imaging=true`, each shared mesh plan lazily caches a wireframe topology excluding selected effects and a complementary effect-only topology. Cache identity uses only the selected descriptors that the individual mesh can reference, so unrelated transient effects do not multiply static or per-mesh cache entries. A sentinel represents reuse of the plan's source topology instead of storing a topology-to-plan back-reference. All mode-3 billboards and mode-5/6/7 descriptors whose complete resident page belongs to the explosion, weapon, jump-jet, or flag CEL catalog use the existing ordinary batched textured emitters; the remaining faces use the unchanged indexed wireframe path. These effects draw after enhanced-imaging lines with normal depth testing and a small polygon offset. Disabling the option retains the legacy wireframe-only behavior, and descriptor qualification uses retained runtime catalog resource ids rather than reading `MW2.PRJ`.
- Enhanced-imaging wireframe visibility is camera-centered and radial rather than camera-forward depth based. The fully lit radius begins at the cockpit near-clip distance and advances over `[renderer] enhanced_imaging_reveal_time` to the native far depth multiplied by `enhanced_imaging_distance_ratio`; defaults are 0.3 seconds and 1.5. Both expanded and indexed line shaders fade through a fixed 0.15-world-unit band, while black occluders and preserved textured effects remain unchanged. Static terrain deliberately retains its polygonal wireframe instead of replacing it with height contours because contour spacing loses small-scale shape detail and converges into broad color at distance.
- Satellite terrain deliberately retains the ordinary cached textured-terrain policy with scene fog disabled. Non-terrain satellite objects keep immutable source face flags, indices, normals, face-to-owner slots, and owner addresses in the topology cache. Live owner class, IFF state, and satellite colors form a separate classification signature; only the alternate face treatment and typed emission bins are rebuilt when that signature changes. Satellite colored outlines and black occluders currently retain the expanded legacy wireframe buffers, while satellite solid mode-4 faces use an expanded Numba-filled stream so the established integer camera-depth palette ramp remains exact. Target-display wireframes also retain the expanded legacy representation.
- Parsed topology caching is bounded to 8192 entries and bulk-evicts the oldest quarter only when that limit is exceeded, avoiding per-hit LRU mutation in the steady path. Primary entity topology keys include the POLY resource id currently installed in the matching native component descriptor, preventing a recycled heap address from aliasing topology belonging to a previous LOD resource. Geometry that cannot be mapped unambiguously to a component descriptor retains exact complete-index-span validation before reuse; target-tree geometry remains conservatively validated as well. Dynamic vertex arrays are intentionally reread even on topology hits because live state can replace or repurpose their backing storage.
- With `[renderer] entity_lod_selection=projected_size`, the primary walk first binds native component nodes to the reusable entity frame, then suppresses only their native body geometry and emits the renderer-selected resident POLY asset into the entity partition with the same live component transform. Projected height uses the authored model radius, active camera projection/zoom, and final output resolution; three pixel thresholds select detail 0 through 3 and per-view history applies hysteresis. Forced `detail0` through `detail3` modes bypass projected selection, while `native` leaves the game's installed geometry untouched and skips the entity snapshot. Main, satellite, MFD, and target views share the same mission assets and current live frame but select independently for their projection; target presentation forces detail 0 and visits only the selected entity.
- Renderer-owned entity material resolution is per entity, not per POLY resource or mech model. Authored textured-face index `0x00` is the camo placeholder and `0x14` is the emblem placeholder. `entity_components.py` compares the matching installed-detail resident WTBO faces with their live native faces once when that entity is first selected, retains the resulting `(camo, emblem)` pair for the mission generation, and includes both values in compiled-asset identity. This contract allows opposing entities that share the same model to retain different camo and insignia; an emblem with no observed live match conservatively remains `0x14`.
- Renderer-owned entity component lifetime follows the live installed-node binding. A component is eligible only while its descriptor has a nonzero installed node, and the live node's hidden bit remains authoritative; a missing node is never synthesized from the resident POLY asset, regardless of whole-entity flags. Destroyed or detached parts therefore leave renderer ownership immediately, while detached debris remains ordinary native scene geometry until the game removes it.
- Matrix-owned local vertex assets are keyed by the consumed block layout prefix `block+0x00..+0x0B` rather than the complete 24-byte header. Native rendering mutates `block+0x10` as live scratch/state, but local vertex decoding consumes only state, vertex/face counts, and face offset from that prefix. Block identity remains topology-owned, while live face headers and complete damage-sensitive index spans retain their existing validation.
- Ordinary dynamic topology reuse compares authored/topology face fields while excluding the native world-normal scratch at `face+0x14..+0x1F`. When only those world normals change, one compiled pass decodes them into the persistent mode-0/1, mode-4, and mode-5/6/7 deferred packages instead of rebuilding Python face topology. Source flags, counts, index offsets, local-normal fields, and owner pointers remain exact invalidation inputs. Satellite and wireframe paths retain conservative complete-header matching, and damage-sensitive index-span validation is unchanged.
- Matrix-owned vertex assets retain their last transformed world-position array keyed by the exact entity-matrix bytes. An unchanged matrix reuses that immutable typed array; any rotation or translation byte change immediately allocates and fills a replacement through the compiled transform. Cached-world fallback paths remain live guest-memory reads and do not use this reuse rule.
- Mission CPU state owns a persistent ordinary mode-5/6/7 aggregate layout. Stable face/descriptor topology retains grouped vertex, index, and primitive-contribution arrays across frames; changed matrix-owned world-position blocks update only their descriptor ranges, changed world-normal generations update only their face ranges, and unchanged contributions are retained unless positional lighting or global light/fog inputs require recomputation. Descriptor resolution, indexed texture animation, palette/remap state, and GPU upload remain live and independent of this CPU geometry reuse. Layout identity changes, mission generation changes, and topology/index changes rebuild the aggregate conservatively.
- Ordinary mode-4 and indexed-flat dynamic output use the same mission-owned persistent-range policy. Mode 4 refills only block ranges affected by world-position, world-normal, or relevant light/fog changes. Indexed geometry retains stable position and index arrays; changed world-position blocks update only their position ranges, mode-0 palettes remain topology-owned, and mode-1 primitive palettes refresh for affected blocks or whenever camera/light/fog shading inputs change. Layout/topology changes rebuild complete family buffers, and satellite/wireframe output remains on its separate conservative paths.
- Static final-buffer cache keys include the extraction schema, wireframe policy, indexed-wireframe policy, mesh-local enhanced-effect descriptor selection, satellite policy, primitive gates, block identity, and block header. The ordered per-frame list of those keys is the static geometry signature. Static VBOs, EBOs, descriptor-grouped meshes, and primitive textures upload only when that signature changes or the wireframe-build policy changes; otherwise their GL objects are reused. Palette and resolved texture-image updates are independent of the geometry signature and do not invalidate static geometry.
- Dynamic GL buffers orphan their existing storage before each frame write to avoid waiting on queued GPU use. This applies to dynamic ordinary families and the indexed enhanced-imaging position/EBO buffers. Empty dynamic updates release stale content. A rendering-mode transition changes the static signature and/or wireframe-build policy, causing old static wireframe resources to be replaced or cleared; OpenGL context recreation releases and rebuilds every program, texture, VAO, VBO, and EBO.
- As a correctness-first workaround for occasional wrong explosion frames, nodes containing mode-3 faces bypass the static geometry cache, mode-3 textured meshes are resynchronized to GL every frame, and mode-3 indexed textures are force-written every frame after descriptor/page resolution. Texture objects are still reused when their dimensions match.
- Current performance diagnostics split the render hook timing into snapshot/extraction, palette upload, scene clear, sky draw, geometry upload, geometry draw, total scene render, and compositor blit timings in `renderer_debug.log`. Active target extraction also periodically emits `target_perf` timing for target resolution, tree walking, topology, vertex read/decode/transform, face emission, batching, upload, draw, and overlay work.
- `MW2_RENDERER_CACHE_STATIC_GEOMETRY=1` is the current default. Static node final emitted vertices are reused after the first extraction for each static block, while dynamic entity/cockpit nodes still update every frame. As a current billboard-debug workaround, nodes containing mode-3 faces are treated as dynamic so billboard geometry is always reread from the live node list and reuploaded; referenced mode-3 descriptor textures are also still resolved each frame so GL textures can follow game cache churn. Terrain/static geometry keeps its cached per-face lighting contribution, but modes 4/5/6/7 now apply enhanced fog in the shader from the current camera position so fog remains live while panning and moving.

## Current Passes

- The render-aware hook at `0x0002CEB7` (HUD entry) snapshots camera, focal length, palette, sky/ground palette indices, sky/ground/gradient gates, and the mission gradient height at `0xA7154`.
- Radar mode 4 replaces the normal perspective scene with a north-up orthographic satellite camera centered on the authoritative player entity. Persistent external camera mode 1 takes precedence only when the special automatic-camera latch at `0x0A62B4` is nonzero, identifying the player-destruction orbit; manually selected external mode still yields to the temporary satellite camera. Full-screen weapon mode 3 does not move the satellite center. Regular-radar and satellite FOV rays share the scene's effective horizontal-FOV resolver, including output aspect and the configured clamp. Satellite FOV uses the persistent cockpit zoom at `0x0A6FA0`, not the active weapon camera focal field, and draws its resolved rays directly to the active satellite target. Their endpoints extend beyond the crossed viewport edge by a stroke-aware margin so wide or antialiased line caps cannot appear onscreen. Selected-target anchors use the same resolution-aware orthographic projection as satellite scene geometry: onscreen targets use the generated symmetric cross at the final output-pixel center, while offscreen targets use the shared full-size generated caret for the crossed viewport edge with normal target-classification coloring.
- Satellite object rendering classifies every non-terrain face from its owner class and the live primary/secondary IFF tables. Selected classes render as black occluders plus configured colored outlines; effect classes preserve their source modes; other classes use the documented satellite mode-4 palette ramp. Node-level hidden/disabled/class omissions run before extraction, and point/line gates use the live renderer globals. These decisions use authoritative owner/entity tables with only the spec-required unknown-class fallback; there is no proximity matching.
- Satellite mode-3 effects use the `V/U` control roles to build axis-aligned screen-space squares, retain live texture animation, and render animated effect layers late and double-sided to approximate native painter ordering over the depth-buffered scene. Mode-1 explosion chunks use the computed low-byte palette index directly.
- Native satellite damage state 2 is latched after the native HUD pass, when the selected degraded window is valid. The next scene frame renders satellite geometry plus its FOV and ordinary blip overlays into one lazily allocated scratch color/depth target. By enhanced-renderer policy, both the on-screen selected-target cross and offscreen selected-target caret are suppressed in this degraded presentation. Its 1024x768 logical reference maximum is 320x240; target height scales by `output_height / 768`, target width follows the physical output aspect, and each intermediate native damage window retains its proportional extent inside that maximum. The scratch target follows the active scene sample scale. Its reduced region is nearest-stretched into the staging scene target with antialiasing disabled and linearly sampled with 4x SSAA. Range/bearing text and every non-radar HUD layer are omitted during degradation. The compositor remains presentation-only and consumes the ordinary atomically published full-size scene/transparent-overlay pair.
- By enhanced-renderer policy, satellite terrain reuses the normal cached textured terrain geometry with scene fog disabled instead of reproducing native untextured mode-4 terrain. Satellite mode also intentionally ignores enhanced-imaging terrain wireframe state. It retains the calculated native far depth as metadata but renders with the enhanced orthographic far plane and the standard enhanced near plane; the native satellite near plane is intentionally not reproduced because it cuts holes through mountain peaks.
- The same hook walks world geometry, computes palette indices for modes 0, 1, and 2, computes continuous per-face light contributions for modes 4, 5, 6, and 7, resolves indexed textures for modes 3, 5, 6, and 7, uploads the palette and, unless disabled by diagnostics, updates static/dynamic geometry buffers before rendering the full scene into the offscreen scene framebuffer and then refreshing the HUD overlay.
- HUD camera draws are issued after the main scene and before the HUD overlay. Rear/down MFD views reuse the main extraction's static and ordinary dynamic draw sets, omitting the separately uploaded main-view-only player subtree without another node-list walk; their renderer-owned entity partition is selected from the same live frame for the pane's projected resolution. Weapon MFD reuses the complete uploaded current-scene geometry. Target geometry is prepared later at the native target-helper callsite; entity targets select detail 0 from the shared frame and resident mesh plans, while unsupported targets retain the native target-tree fallback. MFD and target views pass their camera, partition set, background, and lighting mode to the same camera-target renderer before their overlay regions are refreshed for publication. HUD helper near planes are derived from focal length and pane width in the native `depth * 4` convention, while their native inherited far value is retained only as metadata and rendering uses the enhanced far policy. Full-screen weapon view needs no separate framebuffer or renderer mode: native camera update publishes the ordnance camera as the active main-scene camera, which the ordinary scene snapshot consumes.
- Target and MFD camera damaged-video substitution reads the native panel/latch and shared animation-record state without writing game memory. The early HUD snapshot suppresses normal pane content and records its current RLE frame timing; the existing late HUD hook resolves and draws that request after native HUD has loaded the shape resource. Multi-frame `1.10` shapes use 8-byte descriptors whose first dword is the relative frame offset.
- Sky hemisphere and horizon gradient-cylinder meshes are static per GL context. Palette indices are per-frame uniforms, so palette changes and sky/ground index changes do not rebuild mesh buffers.
- The compositor does not read game memory or upload scene palette/geometry data. Its ordinary path only combines the latest atomically published scene/overlay texture pair in the supplied mod viewport, so the independent VGA presentation cadence cannot observe staging targets. During mission loading it instead clears that viewport and draws the already-snapshotted indexed loading textures directly to `ctx.screen`; no intermediate loading FBO is used.
- Scene rendering clears to black unless `ground_visible` is nonzero, in which case it clears to `palette[gnd_pal_idx]`.
- If `sky_visible` is nonzero, scene rendering draws a camera-oriented sky hemisphere sampled from `palette[sky_pal_idx]`.
- If `gradient_enable`, `gradient_band_enable`, gradient height, and the palette-index range are all valid, scene rendering draws the horizon gradient cylinder over the sky using interpolated palette texture coordinates.
- Scene rendering uploads and draws the static and dynamic mode-4 geometry buffers over the sky/gradient pass with depth testing from the HUD entry hook.
- The gradient cylinder mesh is normalized and static per GL context. Its Y scale is updated from `gradient_height / 512 * SKY_RADIUS`, using the default focal length even when the camera is zoomed.
- With no frame published yet, the published scene and overlay targets are initialized to black and transparent respectively before the compositor blits them.

## Known HUD Camera-View Issues

- The default flat target display is close to native but its lighting still does not match exactly; normal interpretation, light direction/type, and related scene-lighting behavior need further investigation. The optional textured three-point-light path remains disabled because some target polygons flicker and the result is harder to read than the native flat display.
- Nearly edge-on ordnance fins can rasterize thinner than in the software renderer, similarly to terrain cracks exposed by stricter OpenGL coverage rules.
- Active target mode 2 performs a separate target-tree extraction and upload. Its observed runtime cost needs dedicated profiling because internal tests do not exercise the target display.
- The historical external-view mech-leg corruption was caused by primary entity LOD replacement recycling polygon-block storage while the topology cache still identified entries only by block address and layout. Component-descriptor POLY resource identity now separates those cache entries, with exact index-span validation retained for unmapped geometry.
